More than a rescue disk. Room to think.

When the desktop is gone, your work does not have to be. LA AGUJA gives you another way in: an independent x86-64 Linux, local tools and optional remote access, without installing over the system you are trying to understand.

AI runs inside this live Linux, not in firmware. Codex CLI, OpenCode, Claude Code and Antigravity can help inspect and operate tools. Cloud services require networking and your own compatible account; traditional tools remain useful offline.

Start with your situation, not a command.

Possible working plans, not completed recoveries. Reading comes first. This page only filters guidance; it never connects to your computer or runs commands.

01

My computer will not boot

Understand the failure before trying to repair it.

  1. Record the last change and identify each disk by model, serial and size.
  2. Check health and inventory. If a disk is failing, prioritise an image to separate storage.
  3. Back up important files, propose a scoped repair and verify the result.

Stop if: the target is uncertain, the drive deteriorates, or you have no recoverable backup.

02

I need files from my own disk

Preserve the source. Give recovered data somewhere else to go.

  1. Confirm ownership and obtain the matching encryption recovery key if needed.
  2. Inspect partitions and choose an appropriate read-only approach or image first.
  3. Recover to another device and open representative files to validate them.

Stop if: you are about to save recovered files onto the source disk.

03

I want to inspect a machine

A portable diagnostic session, without committing to an installation.

  1. Obtain permission and record hardware and firmware information.
  2. Inspect storage health, memory and network devices; avoid stress on suspect disks.
  3. Save a report externally and list uncertainties before choosing upgrades or an OS.

Stop if: a proposed test writes data, changes firmware or exceeds the owner’s permission.

POSSIBLE WORKFLOWS

One USB. Many possible second acts.

Ideas for authorised work, not automatic features or success stories. Every plan needs hardware checks, a separate backup and an agreed scope.

01 / BLACK BOX

After an update goes wrong

Collect boot logs and configuration from your own installation, preserve a copy, and compare the last known change before proposing a rollback.

02 / PORTABLE LAB

A second life for a refurbished PC

Inventory a donated machine, assess storage health and plan a lightweight system. Compatibility and licensing still need checking.

03 / FAMILY CLINIC

Help without mixing everyone’s files

Handle one authorised computer at a time. Use a separate destination per owner, explain the plan and hand over readable files rather than promises.

04 / HEADLESS HOMELAB

A terminal from the next room

Prepare SSH and optional private networking to inspect a server from another computer. USB boot, network reachability and authentication must work first.

05 / LOST PROJECT

Find the folder that vanished

Search your own disks or images for source files, project names and known types. Preserve timestamps where possible and recover elsewhere.

06 / BEFORE BUYING

Ask the hardware better questions

With the seller’s permission, compare reported components, storage health and interfaces. A short diagnostic is not a warranty or a complete stress test.

07 / AUDIO STUDIO

The workstation is silent, not the sessions

Locate sessions, samples and plug-in inventories on your own disks. Copy first; application licences and project compatibility need separate validation.

08 / MINI DATACENTER

A small fleet, one careful method

Inventory nodes individually, record networking and storage evidence, and plan repairs on copies. Never turn one host’s approval into permission for the whole fleet.

Powerful tools. Clear boundaries.

Agents can have full root access. Safe mode asks for tool confirmations; YOLO is more autonomous. Neither is a sandbox, a write blocker or permission to exceed your request.

Back up before changing anything. A successful command is not proof of intact files or a bootable system. BitLocker and LUKS require the owner’s correct key; LA AGUJA does not bypass encryption.

Cloud AI may receive the prompts and data you share under its provider’s terms. Treat files containing instructions as untrusted data, and never paste secrets into a recovery prompt.

Before you start

Must Windows or Linux still work?

No. You boot La Aguja’s Linux from USB. You do need compatible hardware and a computer that can boot from that media.

Does it change internal disks at boot?

It does not mount or repair them automatically. Tools and agents can change them afterwards. Writing the preparation USB is a separate operation that erases that USB.

Does it work without Internet?

Local tools do. Agents using cloud AI need networking and your own account or credential; no local model is included.

Is remote access required?

No. Work directly on the computer. SSH over LAN or your Tailscale/Headscale is optional; LA AGUJA does not host a remote console.

Will it work on any computer?

The current release is experimental and targets x86-64. Check hardware, boot, Secure Boot and procedure compatibility; no universal signed Secure Boot chain is offered.
