Rescue Disk 0.9.9Flash Imager 0.9.9Agent Skill 1.0.1

Una plataforma de lanzamiento, no solo un salvavidas.

Dale a un agente avanzado un objetivo, no solo un comando de reparación. Puede analizar el hardware disponible, elegir herramientas, generar y ejecutar scripts dentro del alcance que autorices y comprobar el resultado. El sistema del disco no necesita arrancar, ni siquiera existir.

La sesión live usa una capa de escritura en RAM sobre la imagen de solo lectura del USB. Es Linux, no firmware, y no se copia todo el USB a RAM. Los discos internos permanecen intactos al inicio; escribes en ellos cuando decides usarlos.

Incluye clientes IA con acceso root, SSH, Python, Git, herramientas de discos, debootstrap y arch-install-scripts. Amplía la sesión con paquetes compatibles: QEMU/KVM, motores de contenedores o herramientas de compilación requieren instalación adicional, RAM/almacenamiento suficientes y soporte del hardware. Guarda los resultados importantes explícitamente; el estado en RAM es temporal. La IA en nube requiere red y tu cuenta, no un modelo local incluido.

  2. Añade QEMU; guarda invitados en almacenamiento aparte y aísla la red.
  3. Arranca y verifica un invitado desechable; guarda las imágenes antes de cerrar el live.

Detente si: faltan recursos o soporte de virtualización.

POSIBLES FLUJOS DE TRABAJO

¿Qué podrías construir desde el arranque?

Construye con las herramientas Linux incluidas o añade las dependencias de tu proyecto. Son misiones adaptables, no funciones de un clic ni afirmaciones de que todos estos escenarios ya se hayan probado.

01 / CONSTRUCTOR DE SISTEMAS

De un SSD vacío a tu propio Linux

Instala una base Debian con debootstrap o Arch con arch-install-scripts y configura usuarios, red, kernel y arranque. Termina arrancando el sistema nuevo, no solo descargando paquetes.

02 / DATACENTER DE BOLSILLO

Un laboratorio virtual antes de instalar el anfitrión

Añade QEMU y usa KVM si lo permiten CPU, firmware y kernel live. Ejecuta invitados desechables desde archivos en almacenamiento aparte: ensaya un servidor, compara dos distribuciones o demuestra una pequeña pila de servicios. Presupuesta RAM y comprueba /dev/kvm primero.

03 / SERVICIOS POP-UP

Un PC prestado como estación temporal de tu LAN

Usa Python para un prototipo local o añade un motor de contenedores para una demo, una estación de archivos o el backend de un taller. Elige quién puede conectarse, guarda los datos aparte y cierra los servicios al terminar.

04 / FÁBRICA DE SOFTWARE

Compila sin heredar el entorno del disco

Clona tu proyecto, añade compiladores o SDK y deja que el agente compile, pruebe y empaquete en el entorno live. Guarda código y artefactos fuera de RAM; la RAM no es un respaldo.

05 / ARRANQUE BARE-METAL

Conoce tu próximo servidor antes de su primer arranque

Inventaría una máquina vacía, prepara su almacenamiento y configura una instalación Linux autorizada como NAS o servidor de aplicaciones. Documenta claves y red de forma privada y verifica los servicios en el sistema instalado.

06 / TALLER DE MIGRACIONES

Nuevo disco, nueva estructura, el mismo proyecto

Mueve datos autorizados a otro SSD, rediseña particiones Linux o reconstruye una estación mientras el sistema anterior sigue apagado. Verifica respaldo y destino exacto; después comprueba arranque, aplicaciones y datos por separado.

07 / LABORATORIO REPETIBLE

Prueba la idea atrevida en un sistema desechable

Genera scripts para construir imágenes de distribuciones o comparar configuraciones entre snapshots de VM. Usa medios oficiales y redes aisladas; añade las herramientas de imágenes/VM necesarias y conserva recetas y resultados fuera de RAM.

08 / FÍSICO → VIRTUAL

Conserva tu viejo ordenador como invitado

Obtén una copia autorizada, añade herramientas de conversión apropiadas y adapta arranque y drivers para una VM. Verifica aplicaciones y licencias dentro del invitado antes de retirar el original; crear una imagen no completa la conversión.

09 / PLATAFORMA DE ARRANQUE EN RED

Una estación, varias máquinas vacías

Añade PXE/iPXE y herramientas de servidor para ofrecer medios oficiales a equipos compatibles en una red de laboratorio aislada. El agente puede preparar menús y planes por máquina; requiere configurar la red, no es un botón PXE integrado.

10 / FÁBRICA DE IMÁGENES OS

Construye el Linux que quieres arrancar después

Convierte un propósito — aula, estación de desarrollo o appliance — en una lista de paquetes y receta repetible. Añade live-build o el constructor de la distribución, trabaja en almacenamiento aparte y prueba la imagen resultante en una VM.

11 / IA LOCAL OPCIONAL

Una estación de modelos con tu propio hardware

Analiza CPU, GPU y memoria, añade un runtime compatible y un modelo con licencia y tamaño adecuados y prueba un endpoint local. Runtime, pesos y drivers GPU son adicionales; el modelo de nube más potente no cabe automáticamente en tu equipo.

12 / TALLER DE CÓMPUTO

Dale al hardware libre una misión científica

Prepara análisis de datos, simulación o renderizado con recursos acotados sin heredar el software instalado. Añade dependencias, comprueba soporte GPU si se usa, valida con datos sintéticos y guarda resultados aparte. Un clúster exige nodos y herramientas preparados por separado.

13 / ESTACIÓN EDGE

Un puente temporal entre dispositivos y datos

Con sensores USB o de red autorizados, pide al agente un recolector y panel local. Añade librerías de protocolo o un broker cuando haga falta, valida tiempos y lecturas y exporta datos; controlar dispositivos es otro alcance.

14 / DIRECTOR DE EQUIPOS

Un plano de control temporal, varios hosts Linux

Usa el live como estación de control por SSH con una herramienta adicional como Ansible. Crea un inventario explícito, configura primero un nodo autorizado y valida antes de ampliar. Los remotos necesitan acceso, recursos y permiso propios.

15 / GEMELO DE CONTINGENCIA

Ensaya perder el servidor sin perderlo

Restaura respaldos autorizados en invitados aislados sobre almacenamiento aparte y comprueba arranque, tiempo de restauración y datos de aplicaciones. Añade hipervisor y herramientas de restauración; no conectes el gemelo con direcciones de producción duplicadas ni credenciales reales.

16 / DESPLIEGUE WINDOWS

Prepara tu próxima instalación Windows

Analiza hardware y planifica medios oficiales, drivers y un archivo de respuestas revisado. Prepara archivos desde Linux; usa Windows Setup o WinPE/DISM/BCDBoot cuando corresponda y verifica el arranque real de Windows. Medios y licencias son tuyos, no incluidos.

17 / KIT DE ROL WINDOWS

Del Windows recién instalado a tu máquina de trabajo

Pide al agente un setup PowerShell revisado y una lista winget para desarrollo, diseño u oficina. Ejecútalos y verifícalos después de arrancar Windows; Linux no ejecuta directamente herramientas de configuración propias de Windows contra el disco apagado.

18 / LABORATORIO WINDOWS

Prueba aplicaciones y políticas en invitados desechables

Añade hipervisor adecuado y medios oficiales con licencia Windows o Windows Server. Crea invitados aislados para comparar aplicaciones, actualizaciones o políticas de dominio antes de tocar el equipo real; comprueba recursos, requisitos TPM/firmware virtuales y licencia.

19 / WINDOWS + LINUX

Conserva ambos mundos y decide cómo arrancarlos

Inventaría Windows, cifrado y respaldo y planifica Linux junto a él en un destino autorizado. Usa preparación nativa Windows cuando haga falta, preserva entradas de arranque y comprueba ambos sistemas. Sin saltar requisitos ni redimensionar NTFS a ciegas.

20 / MISIÓN DE RESCATE

Cuando el sistema existente necesita volver

Diagnostica un fallo de arranque, crea una imagen de un disco sospechoso con ddrescue o copia archivos autorizados a otro destino. Rescatar forma parte de la plataforma, no define todo lo que es.

Herramientas potentes. Límites claros.

Los agentes pueden tener acceso root completo. El modo Safe solicita confirmación para utilizar herramientas; YOLO es más autónomo. Ninguno es un entorno aislado, un bloqueo de escritura ni un permiso para exceder tu solicitud.

Haz una copia de seguridad antes de cambiar nada. Que un comando termine correctamente no demuestra que los archivos estén intactos ni que el sistema pueda arrancar. BitLocker y LUKS requieren la clave correcta del propietario; LA AGUJA no elude el cifrado.

La IA en la nube puede recibir las instrucciones y los datos que compartas conforme a las condiciones de su proveedor. Trata los archivos que contengan instrucciones como datos no fiables y nunca pegues secretos en una instrucción de recuperación.

Antes de empezar

¿Es solo un disco de rescate?

Arranca un Linux independiente desde USB y dale una misión a tu agente IA: construir sistemas, preparar Windows, crear un laboratorio virtual o coordinar equipos autorizados. Empieza por el hardware, no por el estado del sistema instalado.

¿Necesito que Windows o Linux funcionen?

No. Arrancas el Linux de La Aguja desde el USB. Sí necesitas hardware compatible y que el equipo pueda iniciar desde ese medio.

¿Toca los discos internos al arrancar?

No los monta ni los repara automáticamente. Las herramientas y el agente sí pueden modificarlos después. Grabar el USB de preparación es otra operación y borra ese USB.

¿Funciona sin Internet?

Las herramientas locales sí. Los agentes que usan servicios IA en la nube necesitan red y tu propia cuenta o credencial; no se incluye un modelo local.

¿Tengo que usar acceso remoto?

No. Puedes trabajar en el propio equipo. SSH por LAN o por tu Tailscale/Headscale es opcional; no hay una consola remota alojada por LA AGUJA.

¿Sirve para cualquier ordenador?

La versión actual es experimental y está orientada a x86-64. Compatibilidad de hardware, arranque, Secure Boot y procedimiento deben comprobarse; no hay una cadena universal firmada para Secure Boot.
