Una piattaforma di lancio, non solo un salvagente.

Dai a un agente avanzato un obiettivo, non solo un comando di riparazione. Può analizzare hardware, scegliere strumenti, generare ed eseguire script nel perimetro autorizzato e verificare i risultati. Il sistema installato non deve avviarsi, né necessariamente esistere.

La sessione live usa uno strato scrivibile in RAM sopra l’immagine USB di sola lettura. È Linux, non firmware; l’intera USB non viene copiata in RAM. I dischi interni restano intatti all’avvio; decidi tu quando scriverci.

Include client IA con accesso root, SSH, Python, Git, strumenti per dischi, debootstrap e arch-install-scripts. Aggiungi pacchetti compatibili: QEMU/KVM, motori di container e strumenti di compilazione richiedono installazione aggiuntiva, RAM/spazio sufficienti e hardware compatibile. Salva esplicitamente i risultati importanti; la RAM è temporanea. L’IA cloud richiede rete e il tuo account; nessun modello locale è incluso.

Usa gli strumenti Linux inclusi o aggiungi le dipendenze del progetto. Sono missioni adattabili, non funzioni con un clic né scenari tutti già collaudati.

01 / COSTRUTTORE DI SISTEMI

Da un SSD vuoto al tuo Linux

Installa una base Debian con debootstrap o Arch con arch-install-scripts. Configura utenti, rete, kernel e avvio e verifica il boot del nuovo sistema.

02 / DATACENTER TASCABILE

Un laboratorio virtuale prima di installare l’host

Aggiungi QEMU e usa KVM se CPU, firmware e kernel live lo consentono. Salva le immagini su storage separato, prova distribuzioni o piccoli stack di servizi; controlla /dev/kvm e la RAM.

Un PC disponibile diventa una stazione LAN

Usa Python per un prototipo locale o aggiungi un motore di container per una demo, una stazione di file o un laboratorio. Definisci accessi, salva i dati separatamente e arresta i servizi alla fine.

04 / FABBRICA SOFTWARE

Compilare senza ereditare l’ambiente installato

Clona il progetto, aggiungi compilatori o SDK e fai compilare, testare e pacchettizzare all’agente. Salva codice e artefatti fuori RAM; la RAM non è un backup.

05 / AVVIO BARE-METAL

Il tuo prossimo server prima del primo avvio

Inventaria una macchina vuota, pianifica lo storage e configura un’installazione Linux autorizzata come NAS o server applicativo. Conserva i segreti privatamente e verifica i servizi dopo il boot.

06 / OFFICINA DI MIGRAZIONE

Nuovo disco, nuova struttura, stesso progetto

Migra i dati autorizzati su un SSD o ridisegna partizioni Linux con il vecchio sistema spento. Verifica backup e destinazione, poi avvio, applicazioni e dati.

07 / LABORATORIO RIPETIBILE

Prova l’idea audace su un sistema usa e getta

Genera script per immagini di distribuzioni o confronta configurazioni con snapshot di VM. Usa media ufficiali, reti isolate e strumenti aggiuntivi; conserva ricette e risultati fuori RAM.

08 / FISICO → VIRTUALE

Conserva il vecchio PC come ospite

Crea una copia autorizzata, aggiungi strumenti di conversione e adatta avvio e driver a una VM. Verifica applicazioni e licenze prima di dismettere l’originale; una sola immagine non conclude la conversione.

09 / AVVIO DI RETE

Una stazione, più macchine vuote

Aggiungi PXE/iPXE e strumenti server per fornire media ufficiali su una rete isolata. L’agente prepara menu e piani per macchina; serve configurazione di rete, non un pulsante PXE integrato.

10 / FABBRICA DI IMMAGINI OS

Costruisci il prossimo Linux da avviare

Trasforma aula, sviluppo o appliance in pacchetti e ricetta ripetibile. Aggiungi live-build o il costruttore della distribuzione, usa storage separato e testa l’immagine in VM.

11 / IA LOCALE OPZIONALE

Una stazione di modelli sul tuo hardware

Controlla CPU, GPU e memoria, aggiungi runtime compatibile e modello con dimensioni e licenza adeguate e prova localmente. Runtime, pesi e driver sono aggiuntivi; il modello cloud più forte non entra automaticamente nel PC.

12 / OFFICINA DI CALCOLO

Una missione scientifica per hardware libero

Prepara analisi, simulazione o rendering con risorse definite senza ereditare il software installato. Aggiungi dipendenze, verifica GPU, valida con dati sintetici ed esporta risultati. Un cluster richiede nodi e strumenti preparati separatamente.

13 / STAZIONE EDGE

Un ponte temporaneo tra dispositivi e dati

Con sensori USB o di rete autorizzati, crea raccoglitore e dashboard locale. Aggiungi librerie o broker, verifica tempi e letture ed esporta dati; controllare dispositivi è un altro incarico.

14 / DIRETTORE DI SISTEMI

Controllo temporaneo di più host Linux

Usa il live come stazione SSH con automazione aggiuntiva come Ansible. Crea un inventario, configura un nodo autorizzato e verifica prima di estendere. Ogni remoto richiede accessi, risorse e permessi propri.

15 / GEMELLO DI CONTINUITÀ

Simula la perdita del server senza perderlo

Ripristina backup autorizzati in ospiti isolati su storage separato e verifica avvio, tempi e dati applicativi. Aggiungi hypervisor e strumenti; niente indirizzi di produzione duplicati o credenziali reali.

Prepara la prossima installazione Windows

Verifica hardware, media ufficiali, driver e file di risposte revisionato. Prepara file da Linux; usa Windows Setup o WinPE/DISM/BCDBoot quando serve e controlla un vero avvio. Media e licenze non sono inclusi.

17 / KIT WINDOWS

Dal Windows nuovo alla macchina di lavoro

Chiedi script PowerShell verificati e lista winget per sviluppo, creazione o ufficio. Esegui e verifica dopo l’avvio Windows; Linux non esegue direttamente strumenti nativi Windows su un disco offline.

18 / LABORATORIO WINDOWS

Prova applicazioni e criteri in ospiti usa e getta

Aggiungi hypervisor adatto e media ufficiali con licenza Windows o Windows Server. Confronta applicazioni, aggiornamenti o criteri di dominio in isolamento; verifica risorse, TPM/firmware virtuali e licenze.

19 / WINDOWS + LINUX

Due mondi con un piano d’avvio esplicito

Inventaria Windows, cifratura e backup, poi pianifica Linux accanto su destinazione autorizzata. Usa preparazione nativa Windows quando serve, conserva le voci d’avvio e prova entrambi. Nessun aggiramento o ridimensionamento NTFS alla cieca.

20 / MISSIONE RECUPERO

Quando il sistema esistente deve tornare

Diagnostica un guasto di avvio, crea un’immagine con ddrescue o copia file autorizzati altrove. Il recupero è parte della piattaforma, non tutta la sua identità.

Strumenti potenti. Limiti chiari.

Gli agenti possono avere accesso root completo. La modalità Safe chiede conferme per l'uso degli strumenti; YOLO è più autonoma. Nessuna delle due è un ambiente isolato, un blocco delle scritture o un'autorizzazione ad andare oltre la tua richiesta.

Esegui un backup prima di modificare qualsiasi cosa. Un comando riuscito non dimostra che i file siano integri o che il sistema sia avviabile. BitLocker e LUKS richiedono la chiave corretta del proprietario; LA AGUJA non aggira la cifratura.

L'IA nel cloud può ricevere le richieste e i dati che condividi secondo le condizioni del fornitore. Tratta i file contenenti istruzioni come dati non attendibili e non incollare mai segreti in una richiesta di recupero.

Prima di iniziare

È solo un disco di recupero?

Avvia Linux indipendente da USB e dai una missione all’agente IA: costruire sistemi, preparare Windows, creare laboratori virtuali o coordinare macchine autorizzate. Parti dall’hardware, non dallo stato del sistema installato.

Windows o Linux devono funzionare?

No. Avvii il Linux di La Aguja dalla USB. Servono hardware compatibile e la possibilità di avviare da quel supporto.

Modifica i dischi interni all’avvio?

Non li monta o ripara automaticamente. Strumenti e agenti possono modificarli in seguito. Scrivere la USB di preparazione è un’operazione distinta che cancella quella USB.

Funziona senza Internet?

Gli strumenti locali sì. L’IA cloud richiede rete e il tuo account o credenziale; nessun modello locale è incluso.

L’accesso remoto è obbligatorio?

No. Puoi lavorare sul computer. SSH via LAN o il tuo Tailscale/Headscale è facoltativo; LA AGUJA non ospita una console remota.

Funziona su ogni computer?

La versione attuale è sperimentale e per x86-64. Verifica hardware, avvio, Secure Boot e procedura; non è disponibile una catena Secure Boot universale firmata.
