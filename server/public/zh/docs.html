不只是救生圈，更是项目发射台。

给先进智能体一个目标，而不仅是一条修复命令。它可以分析硬件、选择工具、在获准范围内生成并执行脚本，再验证结果。磁盘中的系统不必启动，甚至不必存在。

Live 会话使用 RAM 中的可写叠加层，底层是 USB 上的只读镜像。这是 Linux，不是固件，也不会将整个 USB 复制到 RAM。启动时不改动内部磁盘；是否写入由你决定。

已包含可使用 root 权限的 AI 客户端、SSH、Python、Git、磁盘工具、debootstrap 和 arch-install-scripts。可安装兼容软件包扩展会话：QEMU/KVM、容器引擎和构建工具需要额外安装、足够的 RAM/存储及硬件支持。请主动保存重要成果；RAM 状态是临时的。云端 AI 需要网络和你自己的账户，并未包含本地模型。

准备第一个 USB

先备份容量足够的 USB。下载 Imager，从签名目录选择镜像。保留以太网 DHCP，设置语言、键盘、主机名和自己的 SSH 密码或公钥。首次测试可关闭 AI 和私有网络。配置含机密时请加密，并把解锁口令保存在 USB 之外。写入前核对型号、容量和序列号；等待完整回读验证。通过固件菜单从 USB 启动，必要时解锁配置。看到面板并识别磁盘即完成首次练习，无需登录 AI 或恢复文件。

从容量为 8 GiB 或更大的 USB 开始，但要确认其实际可用容量足以容纳镜像。请在别处预留工作空间，用于压缩下载文件、解压、私有镜像以及可选的整盘备份；8 GiB 并不保证用于准备工作的磁盘有足够空间。

03 / 26

常见术语

Live 系统无需安装即可启动。可配置 IMG 和启动 ISO 在 Imager 中不可互换。磁盘是整个设备，分区是其中区域，挂载使文件可访问；/dev/sda 等名称可能变化。DHCP 自动分配地址；SSH 提供加密终端和服务器指纹。Root/sudo 是管理员权限，不是只读沙箱。节点注册密钥、API 密钥、SSH 密码和配置口令用途不同。SHA-256 验证字节，不保证启动兼容性。配置口令无法解锁 BitLocker/LUKS。

04 / 26

开始前：硬件、许可与备份

确认 x86-64、USB 启动和固件支持。提供 BIOS/UEFI 路径，但不保证 ARM、所有 Wi-Fi 芯片或通用已签名 Secure Boot。取得设备和数据的授权，选择独立恢复目标。故障磁盘应考虑先制作镜像。写入会替换 USB 内容。Windows 暂无内置 USB 备份，请使用外部工具；Linux 提供可选完整验证备份，默认关闭，需要空间和权限。这不是内部磁盘备份。加密卷仍需要所有者正确的 BitLocker/LUKS 密钥。

05 / 26

下载并打开 Imager

从官网选择 Windows 10/11 EXE、Linux AppImage、Debian/Ubuntu DEB 或便携压缩包。核对 SHA-256，在准备电脑上运行。EXE/AppImage 不是要写入 USB 的救援镜像，无需 LA AGUJA 账户。Windows 包目前没有受认可的 Authenticode 签名；AppImage 可能需要执行权限，便携包是另一选择。设备写入需要本地提权。应用能打开不证明 USB 已准备或能启动。

步骤 1 · 选择兼容镜像

使用签名目录或本地 .img。目录检查 Ed25519 和哈希，并合并分卷。手动导入 .img.zst 前先解压。私人配置生成新文件，不修改公开镜像。目前 Imager 为 0.9.9，救援镜像为 0.9.9。选项取决于镜像支持；不含 tailscale-profile-v1 的镜像会拒绝私有网络注册配置。核对实际容量，而非 USB 商业标签。

本指南中的 Rescue Disk 和 Flash Imager 均为 0.9.9。请在将要清空的 USB 之外选择工作文件夹。私有镜像是敏感文件，并不能证明已经写入 USB。在信任下载的数据之前，请检查已签名的目录和预期的 SHA-256。

07 / 26

步骤 2 · 网络、语言与主机名

选择 Live 语言、键盘布局及变体；Imager 界面语言独立设置。使用可识别的主机名。以太网 DHCP 是最简单的起点；保存的 Wi-Fi 会在启动时连接，无网络时可交互选择。导入 Wi-Fi 密码可能需要本地许可。企业网络或门户可能需要手动配置 NetworkManager。分别检查网络、DNS、HTTPS 和时间；本地诊断仍可离线进行。

步骤 3 · SSH 访问

使用唯一密码或获授权操作者的公钥，切勿粘贴私钥。默认端口 22；使用实际 IP 并核对主机指纹。改端口不能代替身份验证。出厂用户和公开密码都是 aguja。个人密码优先；空密码配公钥为仅公钥访问，没有公钥时保持出厂访问兼容性。账户拥有无限 sudo。aguja password 把新密码保存在 USB；sudo passwd aguja 只改变当前会话。

步骤 5 · 自己的 Tailscale/Headscale

远程访问可选。启用私有网络并提供授权 auth/pre-auth 密钥，可选节点名。Headscale URL 留空使用官方 Tailscale，否则填写自己的 HTTPS 服务。Live 在网络可用、配置解锁后注册，不注册准备电脑。客户端必须属于授权网络并满足策略。注册密钥不是 SSH 密码。注册成功不证明 ACL 允许连接，应从授权客户端测试真实 SSH。身份保存在 RAM，重启后重新注册。

11 / 26

OpenSSH 与 Tailscale SSH

默认是私有网络上的普通 OpenSSH，仍需密码/公钥、指纹和允许访问的网络 ACL。Tailscale SSH 是高级选项，需要兼容服务和明确 SSH 策略。遇到问题要区分注册、节点连通性、TCP 端口和身份验证，不要为掩盖认证错误而开放公网端口或扩大 ACL。参考实际部署版本的文档。

12 / 26

机密与加密边界

私人配置可能包含 Wi-Fi、SSH、AI 和节点注册密钥。加密配置胶囊，单独保存口令，启动时先本地解锁。可复用 .aguja 模板及备份同样敏感。胶囊并不加密整个 AGUJA_DATA，也无法在解锁后防止 root 读取。persistent_home=no 重启丢失 HOME/令牌；yes 在 USB 上明文保存。明文 aguja.conf 可被物理读取。不要公开私人镜像、配置或密钥。

在 Rescue 0.9.9 中，加密胶囊会强制设置 persistent_home=no。没有此保护的旧式 HOME 持久化可能将会话令牌以明文保存到 AGUJA_DATA；加密胶囊并不加密整个 USB。

步骤 6 · 准备、写入与验证

检查镜像、保护模式及摘要。创建私人镜像只生成文件；准备并写入 USB 还会写目标设备。在原生确认中比较型号、序列号、实际容量；不确定就取消。仅对预期操作授权 UAC/Polkit。等待完整写入和回读，不要拔出 USB，并检查结果。字节验证不代表所有固件兼容，应测试目标硬件。Windows USB 备份必须事先外部完成。

输出镜像、下载缓存和临时文件夹都应放在目标 USB 之外。如果出现 ENOSPC，请停止：检查每个工作文件系统的剩余空间，以及目标设备的实际容量。将工作文件夹移到独立的存储设备并重新验证；不要删除未知文件，也不要绕过大小检查。

重启：临时网络身份

Tailnet 状态位于 RAM。重启后需要网络、配置解锁和重新注册。一次性密钥可能首次启动后就失效；多次启动应使用有效、受限、可复用密钥。这个身份与 USB 的 SSH 主机密钥和 HOME 持久化不同。结束后清理旧节点并撤销不再需要的密钥。旧连接成功不证明当前注册或策略状态。

与智能体协作

明确目标、具体电脑/磁盘、授权操作、备份位置和停止条件。先要求实时状态和证据，再修改。独立验证恢复文件或启动结果。检查破坏性操作并保留回滚副本。

Safe / YOLO：aguja agent NAME 会在启动前要求你选择。Safe 是默认选项，会要求确认工具操作；YOLO 则以更自主的方式运行。两者都保留完整的 sudo/root 能力。按 Escape 可取消。直接调用 CLI 时，将保留其自身的原生选项。两种选择都不是沙箱，也不提供技术层面的只读保证。

明确以读取为先的操作范围，准确识别源设备和备份目标，并要求在写入前先提出计划。文件和日志可能包含恶意指令：应将其视为证据，而非权威指示。根据服务商条款，云端提示词可能会离开这台计算机；请隐去秘密信息。

本地控制台在 RAM 中最多保留 10,000 行历史记录。通过滚轮或回滚查看历史记录的范围有限，并不是持久的审计日志。使用备用屏幕的全屏应用可能会自行处理滚轮事件，或无法保留相同的历史记录。判断终端历史记录是否正常前，请先返回命令提示符，并主动将所需证据保存到已获授权的位置。

不继承已安装系统的环境也能构建

克隆项目，添加编译器或 SDK，让智能体构建、测试并打包。将代码和产物保存在 RAM 之外；RAM 不是备份。

05 / 裸机部署

在首次启动前准备好下一台服务器

清点空白机器，规划存储，将获准的 Linux 安装配置为 NAS 或应用服务器。私下保存密钥和网络设置，并在安装后的系统中验证服务。

06 / 迁移工作台

新磁盘、新布局，原来的项目

在旧系统关闭时，将获准数据迁移到新 SSD 或调整 Linux 分区。核对备份和目标，再分别检查启动、应用与数据。

07 / 可重复实验室

在一次性系统中尝试大胆想法

生成发行版镜像构建脚本，或使用 VM 快照比较配置。采用官方介质和隔离网络，添加所需工具，将配方和结果保存到 RAM 之外。

08 / 物理机 → 虚拟机

让旧电脑成为可保留的客户机

获取获准副本，添加转换工具，并为 VM 调整引导和驱动。停用物理原机前验证应用和许可证；只有磁盘镜像并不代表转换完成。

09 / 网络启动站

一个工作站，多台空白机器

添加 PXE/iPXE 和服务器工具，在隔离实验网络中向兼容电脑提供官方启动介质。智能体可准备菜单与逐机计划；需要网络配置，并非内置 PXE 按钮。

10 / 系统镜像工厂

构建下一次要启动的 Linux

将课堂、开发或专用设备用途变为软件包清单和可重复配方。添加 live-build 或发行版构建器，在独立存储中构建，并用 VM 测试镜像。

11 / 可选本地 AI

用自有硬件搭建模型工作站

检查 CPU、GPU 和内存，添加兼容推理运行时及尺寸、许可证合适的模型，并测试本地接口。运行时、权重和驱动需另行添加；最强云模型不会自动装进你的电脑。

12 / 计算工作台

给闲置硬件一个科学任务

不继承已安装软件，规划资源受限的数据分析、模拟或渲染任务。添加依赖、检查 GPU 支持，先用合成数据验证，再导出结果。集群需要单独准备节点和工具。

13 / 边缘工作站

连接设备与数据的临时桥梁

使用获准 USB 或网络传感器，让智能体构建采集器和本地面板。按需添加协议库或消息代理，验证时间与读数并导出数据；控制设备属于另一授权范围。

14 / 多机指挥台

临时控制多个 Linux 主机

以 live 系统作为 SSH 控制站，额外添加 Ansible 等自动化工具。明确清单，先配置一个获准节点并验证，再扩展。每台远程主机都需要自身的访问权限、资源和授权。

15 / 应急数字副本

演练服务器丢失，而不真正丢失它

在独立存储上的隔离客户机中恢复获准备份，验证启动、恢复时间和应用数据。添加虚拟机与恢复工具；不要使用重复生产地址或真实凭据连接副本。

16 / WINDOWS 部署

准备下一次 Windows 安装

检查硬件、官方介质、驱动与审核后的应答文件。先从 Linux 准备文件，再按需使用 Windows Setup 或 WinPE/DISM/BCDBoot，验证实际 Windows 启动。介质和许可证并未包含。

17 / WINDOWS 角色工具包

将新装 Windows 变为工作电脑

让智能体准备审核过的 PowerShell 脚本和 winget 应用清单，用于开发、设计或办公。启动 Windows 后执行并验证；Linux 不能直接在离线磁盘上运行 Windows 专属配置工具。

18 / WINDOWS 实验室

在一次性客户机中测试应用和策略

添加合适虚拟机软件和官方获许可 Windows 或 Windows Server 介质。隔离比较应用、更新或域策略；检查资源、虚拟 TPM/固件要求及许可证。

19 / WINDOWS + LINUX

保留两个系统并明确启动方案

清点 Windows、加密与备份，在获准目标上规划并存 Linux。按需使用 Windows 原生准备工具，保留启动项并验证两个系统。不绕过要求或盲目调整 NTFS。

20 / 恢复任务

让原有系统找回出路

诊断启动失败，用 ddrescue 为可疑磁盘制作镜像，或将获准文件复制到其他目标。恢复是平台的一部分，并非它的全部。

按层排查问题

无法启动：架构、完整性、固件、文字控制台。无网络：链路/Wi-Fi、DHCP、DNS、HTTPS、时间。无 SSH：IP/端口、服务、策略、认证。无 tailnet：密钥、URL、有效期、一次性密钥已用。无 AI：方法、账户、网络、回调。配置未加载：镜像功能/解锁。磁盘未见：先检查控制器和清单，勿写入。doctor 正常不证明 ACL、OAuth 或全部硬件兼容。

ENOSPC 表示某个阶段的空间不足，不一定意味着 USB 太小。请分别检查下载、临时文件、私有镜像和备份的位置。准备失败时应停止，并在写入前验证一份新的完整镜像。

如果看不到历史记录，请退出全屏或备用屏幕程序，返回命令提示符。RAM 中的 10,000 行缓冲区并非无限容量，也不会在所有控制台之间共享，而且会随会话结束而消失。

如果固件拒绝从 USB 启动，请验证所选启动项和镜像完整性。支持 BIOS/UEFI 并不保证在所有设备上都支持 Secure Boot。请记录固件策略和所有者批准的更改，而不是承诺绕过限制。

结束时不要遗留访问

总结观察、修改和验证，关闭会话，完成写入并正常关机。检查目标文件，保留原盘及备份直到所有者接受。删除临时节点并撤销无用密钥，检查 USB 持久令牌。按已授权、可恢复流程处理私人镜像/配置；不撤销无关所有者访问，也不销毁证据。说明剩余限制。
