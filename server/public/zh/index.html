不只是救生圈，更是项目发射台。

给先进智能体一个目标，而不仅是一条修复命令。它可以分析硬件、选择工具、在获准范围内生成并执行脚本，再验证结果。磁盘中的系统不必启动，甚至不必存在。

Live 会话使用 RAM 中的可写叠加层，底层是 USB 上的只读镜像。这是 Linux，不是固件，也不会将整个 USB 复制到 RAM。启动时不改动内部磁盘；是否写入由你决定。

已包含可使用 root 权限的 AI 客户端、SSH、Python、Git、磁盘工具、debootstrap 和 arch-install-scripts。可安装兼容软件包扩展会话：QEMU/KVM、容器引擎和构建工具需要额外安装、足够的 RAM/存储及硬件支持。请主动保存重要成果；RAM 状态是临时的。云端 AI 需要网络和你自己的账户，并未包含本地模型。

01

安装和配置 Linux

用 debootstrap 安装 Debian 基础系统，或用 arch-install-scripts 安装 Arch；配置用户、网络、内核和引导程序，最后实际启动新系统进行验证。

  1. 清点硬件，确认准确目标和备份。
  2. 选择官方介质或已包含的 Linux 安装工具。
  3. 检查分区，配置系统并验证实际重启。

遇到以下情况请停止： 目标或备份不明确。

02

创建虚拟实验室

额外安装 QEMU，在 CPU、固件和 live 内核支持时使用 KVM。将客户机镜像放在独立存储上，试用发行版或小型服务栈；先检查 /dev/kvm 和 RAM 预算。

  1. 检查 RAM、CPU 虚拟化、固件和 /dev/kvm。
  2. 添加 QEMU，将客户机存于独立存储并隔离网络。
  3. 启动并验证一次性客户机；结束会话前保存镜像。

遇到以下情况请停止： 资源或虚拟化支持不足。

03

搭建临时工作台

用 Python 创建本地原型，或额外安装容器引擎运行演示、文件站或工作坊后端。明确访问范围，单独保存数据，结束后关闭服务。

  1. 选择项目、数据或局域网服务及获准用户。
  2. 添加 SDK 或容器引擎，限制监听接口。
  3. 测试结果，导出产物并停止临时服务。

遇到以下情况请停止： 数据仅留在 RAM 或访问超出约定范围。

04

准备下一次 Windows 安装

检查硬件、官方介质、驱动与审核后的应答文件。先从 Linux 准备文件，再按需使用 Windows Setup 或 WinPE/DISM/BCDBoot，验证实际 Windows 启动。介质和许可证并未包含。

  1. 清点硬件、准确目标、备份和 Windows 要求。
  2. 准备官方介质与审核文件，用 Windows/WinPE 执行原生部署。
  3. 启动 Windows，验证驱动、应用和预期配置。

遇到以下情况请停止： 目标或备份不明确。

可选工作流程

从启动开始，你能构建什么？

使用已包含的 Linux 工具，或添加项目所需依赖。这些是可调整的任务构想，并非一键功能，也不是所有场景都已完成测试。

01 / 系统构建

从空白 SSD 到自己的 Linux

用 debootstrap 安装 Debian 基础系统，或用 arch-install-scripts 安装 Arch；配置用户、网络、内核和引导程序，最后实际启动新系统进行验证。

02 / 口袋数据中心

安装宿主系统之前先搭建虚拟实验室

额外安装 QEMU，在 CPU、固件和 live 内核支持时使用 KVM。将客户机镜像放在独立存储上，试用发行版或小型服务栈；先检查 /dev/kvm 和 RAM 预算。

03 / 临时服务

把闲置 PC 变成局域网临时工作站

用 Python 创建本地原型，或额外安装容器引擎运行演示、文件站或工作坊后端。明确访问范围，单独保存数据，结束后关闭服务。

04 / 软件工厂

不继承已安装系统的环境也能构建

克隆项目，添加编译器或 SDK，让智能体构建、测试并打包。将代码和产物保存在 RAM 之外；RAM 不是备份。

05 / 裸机部署

在首次启动前准备好下一台服务器

清点空白机器，规划存储，将获准的 Linux 安装配置为 NAS 或应用服务器。私下保存密钥和网络设置，并在安装后的系统中验证服务。

06 / 迁移工作台

新磁盘、新布局，原来的项目

在旧系统关闭时，将获准数据迁移到新 SSD 或调整 Linux 分区。核对备份和目标，再分别检查启动、应用与数据。

07 / 可重复实验室

在一次性系统中尝试大胆想法

生成发行版镜像构建脚本，或使用 VM 快照比较配置。采用官方介质和隔离网络，添加所需工具，将配方和结果保存到 RAM 之外。

08 / 物理机 → 虚拟机

让旧电脑成为可保留的客户机

获取获准副本，添加转换工具，并为 VM 调整引导和驱动。停用物理原机前验证应用和许可证；只有磁盘镜像并不代表转换完成。

09 / 网络启动站

一个工作站，多台空白机器

添加 PXE/iPXE 和服务器工具，在隔离实验网络中向兼容电脑提供官方启动介质。智能体可准备菜单与逐机计划；需要网络配置，并非内置 PXE 按钮。

10 / 系统镜像工厂

构建下一次要启动的 Linux

将课堂、开发或专用设备用途变为软件包清单和可重复配方。添加 live-build 或发行版构建器，在独立存储中构建，并用 VM 测试镜像。

11 / 可选本地 AI

用自有硬件搭建模型工作站

检查 CPU、GPU 和内存，添加兼容推理运行时及尺寸、许可证合适的模型，并测试本地接口。运行时、权重和驱动需另行添加；最强云模型不会自动装进你的电脑。

12 / 计算工作台

给闲置硬件一个科学任务

不继承已安装软件，规划资源受限的数据分析、模拟或渲染任务。添加依赖、检查 GPU 支持，先用合成数据验证，再导出结果。集群需要单独准备节点和工具。

13 / 边缘工作站

连接设备与数据的临时桥梁

使用获准 USB 或网络传感器，让智能体构建采集器和本地面板。按需添加协议库或消息代理，验证时间与读数并导出数据；控制设备属于另一授权范围。

14 / 多机指挥台

临时控制多个 Linux 主机

以 live 系统作为 SSH 控制站，额外添加 Ansible 等自动化工具。明确清单，先配置一个获准节点并验证，再扩展。每台远程主机都需要自身的访问权限、资源和授权。

15 / 应急数字副本

演练服务器丢失，而不真正丢失它

在独立存储上的隔离客户机中恢复获准备份，验证启动、恢复时间和应用数据。添加虚拟机与恢复工具；不要使用重复生产地址或真实凭据连接副本。

16 / WINDOWS 部署

准备下一次 Windows 安装

检查硬件、官方介质、驱动与审核后的应答文件。先从 Linux 准备文件，再按需使用 Windows Setup 或 WinPE/DISM/BCDBoot，验证实际 Windows 启动。介质和许可证并未包含。

17 / WINDOWS 角色工具包

将新装 Windows 变为工作电脑

让智能体准备审核过的 PowerShell 脚本和 winget 应用清单，用于开发、设计或办公。启动 Windows 后执行并验证；Linux 不能直接在离线磁盘上运行 Windows 专属配置工具。

18 / WINDOWS 实验室

在一次性客户机中测试应用和策略

添加合适虚拟机软件和官方获许可 Windows 或 Windows Server 介质。隔离比较应用、更新或域策略；检查资源、虚拟 TPM/固件要求及许可证。

19 / WINDOWS + LINUX

保留两个系统并明确启动方案

清点 Windows、加密与备份，在获准目标上规划并存 Linux。按需使用 Windows 原生准备工具，保留启动项并验证两个系统。不绕过要求或盲目调整 NTFS。

让原有系统找回出路

诊断启动失败，用 ddrescue 为可疑磁盘制作镜像，或将获准文件复制到其他目标。恢复是平台的一部分，并非它的全部。

强大的工具，明确的边界。

智能体可能拥有完整的 root 权限。Safe 模式会要求确认工具操作；YOLO 模式更为自主。两者都不是沙箱，不会阻止写入，也不意味着可以超出你的请求范围。

开始之前

这只是救援盘吗？

从 USB 启动独立 Linux，给 AI 智能体一个任务：构建系统、准备 Windows、创建虚拟实验室或协调获准电脑。从硬件出发，不依赖已安装系统的状态。

Windows 或 Linux 必须正常运行吗？

不需要。你从 U 盘启动 La Aguja 的 Linux。但硬件必须兼容，并能从该介质启动。

启动时会修改内部磁盘吗？

不会自动挂载或修复内部磁盘。之后的工具和智能体可以修改磁盘。写入准备 U 盘是另一项操作，会清除该 U 盘。

没有互联网也能使用吗？

本地工具可以。云端 AI 需要网络和你自己的账户或凭据；不包含本地模型。

必须远程访问吗？

不需要，可以直接在电脑上操作。局域网或自己的 Tailscale/Headscale 上的 SSH 为可选项；LA AGUJA 不托管远程控制台。

所有电脑都能使用吗？

当前版本为实验性版本，面向 x86-64。需要确认硬件、启动、Secure Boot 和操作流程兼容性；不提供通用签名的 Secure Boot 启动链。
